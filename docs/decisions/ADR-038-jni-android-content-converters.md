# ADR 038 — typed JNI/Android content converters

Status: converter boundary/controller implementation; complete backend acceptance remains open.

Java exposes distinct ConverterFactory and Converter interfaces. Construction receives only a compiled descriptor, an optional verified resource array and cooperative control. The existing SDK owner constructor is shared with recognisers, preserving factory-error containment, returned-owner retirement, bounded resource-array clearing and actual SDK lifetime under the Core resource guard. A converter probes before declaring a bounded, unique, nonempty list of supported output formats. That declaration is frozen for the activated instance. Conversion consumes editable Content JSON and a declared target, returning Converted JSON with its fidelity/unsupported diagnostics. No raw ink, arbitrary Store/Manager capability or file path is supplied to the converter.

The native Host convenience route prepares conversion against its private shared runtime after obtaining an authorised stored source. A move-only Java EngineConversion owns one native scoped job; run consumes it, close cancels it and wrong-host/replayed handles cannot manufacture work. The result envelope retains source block, optional region and revision, adapter descriptor, target, text and unmodified fidelity diagnostics. It does not mutate the notebook or accept a recognition proposal. Native authority/runtime/caller checks apply after the callback and again after encoding, immediately before returning the derivative. Once deliberately delivered to the trusted application, copied output cannot be recalled.

NotebookEngines adds converter activation and typed immutable derivatives on its existing bounded optional worker. Conversion performs no metadata publication and therefore does not mark a cancelled derivative as a possible notebook edit. The operation owns its native job through close/cancellation and checks cancellation before parsing completion. Existing controller queue admission/close rules apply. The unsupported list is copied into an unmodifiable list. Source revision remains explicit; no implicit replacement or equation/code repair occurs. SDK callbacks retain the same local-only, no-telemetry cooperative contract. Uncooperative in-process callbacks and arbitrary unmanaged SDK clones still require separate isolation/lifecycle work.

Consumer rules retain concrete converter callbacks while fixtures remain minified. Robolectric keeps the Java converter interfaces/owner in the JNI parent loader. Actual desktop JNI fixtures cover source identity and literal text, fidelity diagnostics, unsupported formats, malformed/oversized outputs, single use, capture cancellation, callback reentry, exact verified-resource handoff and array wiping, invalid format declaration retirement and preservation of the previous runtime. Android component tests cover typed diagnostics/source preservation, running/queued cancellation, admission and class-loader identity. These are synthetic provider and API-35 simulation checks, not real SDK licensing/quality, ART/device enforcement, performance or complete backend acceptance.
