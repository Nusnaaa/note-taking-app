# ADR 055 — reviewed provider export bundles and durable uncertainty

Status: implemented with focused and complete Android-module verification; catalogue recovery/resource work and backend acceptance remain open.

`NotebookExports` connects the existing native-copy, Markdown/assets and converted-only PDF host/JNI capabilities to a deliberate Android SAF destination. Its bounded optional worker owns rendering/encoding, platform verification, provider calls and private attempt metadata. Backend initialization/close, capture priority and access-policy invalidation include that worker. The native shared transfer slot and revision/current-scope checks remain authoritative; no notebook/model JSON supplies provider or credential capabilities.

A source review precedes destination inspection. Publication requires explicit confirmation, warning/omission acknowledgment and existing native fresh protected-scope proof. Native plaintext protection acknowledgment and optional caller-owned encryption remain explicit. PDF uses caller-supplied local font/page parameters and retains existing fidelity warnings; full canvas/view/PDF-source fidelity is not invented. Provider permission/identity is checked before release and around subsequent operations, without claiming an atomic OS-permission/SQLite transaction.

Every publication uses a new operation UUID and generated folder name. A private SQLite intent is stored before external creation; it contains only format/library/URI/file-size/hash/state metadata, no notebook body, password or recovery key. Folder/file URIs are recorded as they become known. Names and direct parent relationships are checked. Nonempty returned documents are refused, and platform writes request append mode rather than truncation; concurrent changes cause readback mismatch and uncertainty, not an intentional overwrite. No automatic deletion or retry follows an uncertain provider operation.

Each payload file is checked by full readback. A `STEM-export.json` completion manifest, containing expected payload names/sizes/hashes and fidelity metadata, is written last and itself read back. This is a completion convention, not an atomic multi-file provider transaction. `ProviderVerified` means past readback succeeded, not future availability or cloud durability. Descriptor sync acknowledgment is separate. Errors/cancellation after creation begins return `Uncertain`, preserving known destinations and the operation ID. Metadata-acknowledgment success is separate from observed provider success. Closing/cancelling does not retract known outcomes.

Owned artifact arrays and credential copies are cleared; the publication owns a separately erasable recovery-key copy. The password copy is cleared after native encryption, before provider I/O. The key is never included in the manifest or catalogue. Parent-loader rules established for native import cover the existing Java export wrapper classes as well.

Current catalogue limitations remain explicit: discovery is by known operation ID; paged attempt discovery is still required for complete crash recovery. Whole-record JSON storage/update also needs normalization and resource-boundary verification before claiming scalable catalogue behavior. These rough edges do not close full recovery/resource acceptance. Existing artifact/manifest admission limits are engineering bounds, not heap, latency or device SLOs.

Focused tests use actual desktop JNI, real host descriptors and an app-owned synthetic SAF provider under Robolectric API35. They exercise native/encrypted output, Markdown asset references, PDF warnings, raw observations/incorrect authored text, changed permission, fresh verification, corrupt readback, nonempty/racing files, durable uncertainty, metadata namespace integrity and blocked-create ownership retirement. Real providers/devices, full scene/native PDF-source portability and final APK enforcement remain separate. No production H.I., model installation, external inference or automatic OS content backup is enabled. Native format stays13 and library schema stays23; the device-private catalogue has its own purpose/version.
