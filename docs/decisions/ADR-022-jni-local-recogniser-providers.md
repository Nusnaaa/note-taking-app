# ADR 022 — trusted JNI local recogniser providers

Status: native/Java backend integration; Android controller and real SDK adoption remain open.

The trusted Java boundary accepts app-compiled RecogniserFactory/Recogniser implementations. A consented resource-free compiled adapter can be staged through a separate native method; ordinary notebook JSON cannot stage or execute a provider. Activation reserves an exact stored version plan and caller-supplied load/time bounds. Its factory receives the typed descriptor, verified temporary bytes (or null for a resource-free engine), and current callback control. Construction and probe run on the optional calling worker. The Java resource array is cleared after construction. Resource-backed Android picker/import/resume is still a separate unfinished workflow; no new SDK/model is installed by adding these APIs.

Single-use activation/recognition job tokens are host-bound and share native optional source admission. Registry locks cover metadata only. Job insertion holds the host registry through insertion so close either observes the job or prevents it; an idle token cannot appear after close cleanup scanned. Closing a job cancels and retires idle work, without acknowledging global SDK retirement. Running work remains owned until it actually returns. Host close cancels tokens before waiting on the existing source/manager lifetime. Callback control tokens are linked to the exact native scope/runtime/deadline, valid only while a callback executes, and removed afterward. They grant no source/Store/host access.

Recognisers consume ordered InkSnapshot JSON, including original points, observation metadata and source transform, and return bounded RecognitionOutput JSON. The core rechecks modality, limits, current access, exact source revision/fingerprint and runtime validity before storing a pending proposal. Nothing accepts or repairs the output automatically. Runtime control enters Java via a cached class reference acquired on the native caller's Java class loader; attached cleanup workers need no application FindClass. Exceptions and malformed/oversized output become the generic boundary error.

The adapter owns a Java global reference and invokes retire exactly once on actual final SDK retirement, after writer/Manager/registry locks have been released. A failed retirement becomes a contained native retirement failure, not a successful close acknowledgement; SDK diagnostics are cleared. Trusted factories must clean up partial construction on throw, and retire must release every owned SDK resource even when it throws. Hard SDK isolation, arbitrary SDK clones, forced termination and audited egress are not established by this cooperative contract. Drop of an unrun HostRecognitionWork now explicitly queues its payload on the retirement lane, including after the Manager has detached its last independent pin.

Consumer rules retain callback names on concrete providers while allowing their classes to shrink/rename. Desktop JNI fixtures use app-owned synthetic providers; they establish boundary/lifetime behaviour and release classfile shrink compatibility, not model quality, model-use/source-publication rights, ART/device acceptance or the full recognition requirement. Actual eligible local ordered-ink recognisers, converters through JNI, Android optional controllers, durable resource-backed import and shared media/model resource policy remain open.
