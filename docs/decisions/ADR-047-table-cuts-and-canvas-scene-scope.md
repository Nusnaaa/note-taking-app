# ADR 047 — structural table cuts and canvas-bound ink fragments

Status: implementation/component verification in progress; complete scene/export/selection integration and backend acceptance remain open.

`MoveTable` is an explicit structural cut/paste to an entity, exercise or canvas-layer writing target. It reuses the independent-copy construction from ADR046, retaining geometry, source data/provenance, display and lock state. It then hides the retained source block, without deleting its observations or altering its historical owner. Destination IDs are independent. Within a master, creation/hiding is one authoring journal entry; between masters, the two owner-local entries are linked using ADR045. Both halves, raw-row inserts and link metadata share one SQLite transaction. Fresh source revision/owner and source/destination authority apply. Undo/Redo from either owner is atomic and inherits peer-head, protection, branch and retirement rules.

This is not an identity-preserving geometry drag. Existing `transform_selection` remains the within-master geometry operation. External references and group/view bindings continue to identify the retained source; they are not silently redirected into a different authority context. Automatic follow-object rebinding remains open. Hiding a retained source is not secure erasure or removal from its original history/protection scope.

`CanvasTableInkScenePage` adds a display-context guard around ADR046's source/block query. The caller supplies current canvas entity/layer revisions and optionally an embed ID/revision. The backend verifies actual table ownership, object visibility, current layer visibility or the embed's explicit layer override, and current source/parent protection. The guard runs before and after fragment retrieval; stale context fails rather than continuing an old view. The independent raw-source query remains available according to source authority even if a display layer is hidden.

For one embed, fragments compose cell reflow and the block matrix before the recorded embed camera. Camera centre maps to frame centre; zoom is explicit and positive rotation maps a source rightward vector toward positive host y. The frame rectangle is returned as a host-coordinate clip. Original samples remain unmodified and are not destructively clipped. Non-finite derived matrices/points fail. The complete envelope stays within the existing scene wire budget.

Embed reads now authorise actual SQL host/source identities before decoding the payload and reject payload/SQL identity mismatches. Malformed private embed content therefore cannot turn an unauthorised query into a parse oracle. This strengthens the shared embed read boundary, not just the new scene route.

The canvas route binds a direct canvas or a single embedding into its host's logical surface. Multi-ancestor traversal/composed clipping, outer writing-view/screen transforms, flow layouts, follow-object references, full SVG/PDF derivatives and pen/lasso workflows still require implementation and acceptance. No physical-unit inference, raster recognition, new model capability, production Android H.I. or latency SLO is introduced. No persisted field changes; native13/schema22 remain unchanged.
