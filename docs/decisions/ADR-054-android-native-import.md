# ADR 054 — deliberate native-copy import on the Android backend worker

Status: implemented; recovered-source component checks pass and broader validation remains in progress. Full backend acceptance remains open.

`NotebookImports` owns native-copy preparation and publication through the trusted JNI boundary. It admits one executing and one queued optional operation on its own worker. Provider reads, decryption/remapping, typed result parsing and platform verification run away from the authoring executor and UI observer. The backend exposes the controller and retains library ownership through actual retirement, including initialization failure and close. Pen priority and access/policy changes invalidate optional imports and idle reviews. Admission crosses the existing authoring/status barrier and checks current capture/close state before input or publication.

The platform adapter accepts an explicitly supplied content-document URI, checks existing read permission and acquires no persistent grant. Preparation checks permission after reading; publication checks it before native submission. OS permission lookup and SQLite commit are not claimed atomic. Native app authority, generation and confirmation remain authoritative. URI/credentials do not come from notebook/model JSON. This enables no automatic import, external inference, SDK installation, model telemetry or OS content backup.

The caller supplies an input limit up to the existing 64 MiB artifact bound plus 208 envelope bytes, and an operation deadline. These are engineering admission inputs, not device performance or heap guarantees. Owned bounded input and credential copies are cleared after use. Cancellation reaches the native capability, platform signal and open input on a separate bounded cancellation worker. Blocked provider calls retain admission and backend ownership until actual retirement. No mid-call interruption of an uncooperative provider or cryptographic primitive is claimed. Idle reviews retain native deadline/authority checks across confirmation.

Typed summaries expose counts and immutable source-omission lists; omission strings remain untrusted metadata. Publication is one-shot and requires confirmation and omission acknowledgment. Imported identities, protection and observations follow ADR 053, with no automatic scope grants. Operation identity is available before publication; failures indicate when publication may have committed. A known returned receipt survives late cancellation or close. Closing a completed preparation retires its review; closing a receipt observation leaves the durable result observable. A response-loss fault probe targets the boundary after SQL commit, before typed delivery.

The Robolectric runner keeps newer native/export/import wrapper classes in the parent loader, extending its existing JNI-entrypoint policy. Reconstructed tests exercise actual desktop JNI with app-owned synthetic providers under API 35 simulation. Earlier uncommitted results lost with the temporary worktrees do not verify this recovered source. Fresh results are recorded separately under `docs/evidence/continuation-2026-10-27/android-native-import/recovered-component`: eight import tests and 21 ownership/admission tests passed, together with all ten desktop JNI/R8 checks and 63 fixture groups before/after fresh shrinking. These are component checks, not complete backend acceptance. Physical-device, real-provider, final APK and production H.I. acceptance remain separate. Schema stays 23; native interchange stays 13. Provider export publication and remaining portability/scene/resource work remain open.
