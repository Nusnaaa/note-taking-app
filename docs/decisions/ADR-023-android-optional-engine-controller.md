# ADR 023 — Android optional engine controller

Status: recorded backend integration; resource-backed import and real models remain open.

Each NotebookBackend owns one NotebookEngines controller, shared by leases of the same NotebookRuntime backend. A dedicated worker serializes SDK preparation/inference outside BackendWriter and the main thread. At most two controller operations (executing plus queued) are retained; the queue holds one. Descriptor/load/time limits are explicit input/admission bounds, not device performance or model-memory guarantees. The core still owns source-byte admission, current scope, runtime validity, capture priority, generation/revision fencing and SDK retirement. Explicit engine IDs avoid silent fallback. No SDK/model is registered merely by constructing a backend.

Pending results support observation and cooperative cancellation independently. Cancel requests close an attached native job, or prevent a queued operation from starting. A successful native staging/installation/proposal receipt remains observable even when cancellation arrives too late to undo it. Pending observation never cancels its CompletableFuture or silently discards an acknowledged mutation. Failures expose a fixed message and a conservative metadataMayHaveChanged flag once a native metadata attempt may have occurred; they do not claim rollback. Observer interruption requests cancellation and preserves the interrupt state. Repeated observation returns the same immutable receipt. Proposal receipts retain identity/revision only; transcript reads still use current native authorisation.

Controller close prevents admission, cancels queued/running native jobs, and drains its worker. NotebookBackend closes the controller before native shutdown, then waits for it before releasing Android library ownership. Constructor-failure cleanup also owns this lane. An SDK that ignores cancellation keeps actual native/Android ownership until it returns and retires; this is not hard worker termination. Awaiting on the Android main thread or on this controller's own worker is rejected to avoid a self-wait. Existing writer/capture shutdown ordering is preserved.

Native JobControl and the shared Manager remain the authority. Java SDK exceptions are normalized before crossing JNI; controller failures retain no provider exception cause. Staged/Installed receipts describe durable metadata rather than perpetual runtime readiness. Resource-backed picker/import/resume, engine catalogue/default/uninstall workflows, JNI converters, actual eligible ordered-ink recognisers and hard shared-resource isolation remain open. Synthetic desktop-JNI/API-35 fixtures establish component behaviour, not device or real-model acceptance.
