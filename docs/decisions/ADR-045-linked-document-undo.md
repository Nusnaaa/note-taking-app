# ADR 045 — atomic linked Undo across master surfaces

Status: linked-history implementation/component verification in progress; complete backend acceptance remains open.

Cross-master cell Move creates two owner-local journal entries in one SQLite transaction, with reciprocal `edit_links` rows. Each entry retains its own document identity and before/after payloads. Source observations remain independently retained. Copy still changes only the destination and uses its ordinary local history; same-master compound operations retain their existing single journal entry.

Undo or Redo from either participant resolves the pair without exposing a foreign document title or content. Both entries must be active, reciprocal, have matching recorded authoring time/replay state and nonempty changes, and be the corresponding head in each owner's history. Current authority and inherited/block protection apply to both documents. Replay remains one transaction, including revision increments and the two undone flags; any conflict, denial or commit failure rolls back the whole replay. Newer edits in the other document require their own Undo first.

Deleting one journal member, whether through redo-branch replacement, authorised retention expiry or permanent document purge, retires the survivor. A deletion trigger removes the survivor's replay payloads and marks its link as retired, clearing the peer to the zero sentinel; it does not change that document's live blocks, source observations, snapshots or protection. The surviving owner-local entry is a content-free history barrier. It prevents a half-cut replay and prevents Undo/Redo from jumping beyond an unavailable boundary. History depth excludes actions beyond that barrier. A later local branch may retire obsolete redo barriers normally. Purging a participant therefore removes the ability to replay the whole linked operation; it never silently recreates the purged document.

Retirement may disable the coupled Undo even when the surviving document is locked: the coupling can no longer be replayed once a participant's history is gone. This retires only journal capability/payloads; protected live content and original ink remain untouched. The link stores only local/peer integer operation identities and a retirement bit, not foreign document metadata. Retired peer identities are cleared because logical restore can reuse deleted AUTOINCREMENT values; a barrier must never bind a later unrelated operation. Ordinary authorised history queries return local counts, not linked-owner identities.

SQLite/library backup schema22 adds the private `edit_links` table (operation FK, peer ID, retired bit), an index for retirement lookup and the deletion trigger. The table is appended to both backup table contracts, preserving earlier indices. Restore checks active pair reciprocity, distinct owners, time/state consistency and changes; a retired barrier must have a zero peer sentinel and no replay payloads. Classic older headers cannot carry nonempty links. Stream readers refuse a new-table marker under an older header; actual old table sequences remain readable. Legacy SQLite migration creates an empty link table without rewriting ink, receipts or existing journal payloads.

Native subset remains v13: independent-copy exports do not include device-private Undo journals, and no block/stroke/layout field gains a new interpretation. Native copy retains its existing fresh-history behaviour. This is an ordinary persistence/history extension, not a strategy change or permission for production Android H.I. Full selection, whole-table copy and scene/export/resource integration remain open.
