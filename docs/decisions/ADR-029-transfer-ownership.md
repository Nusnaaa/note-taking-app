# ADR 029 — stable transfer ownership through publication

Status: native transfer/publication ownership; deliberate discard and SDK-aware disk reclamation remain open.

Every mutating transfer holds a nonblocking exclusive advisory file lock on `<id>.owner.lock` in the canonical private depot. This is a separate stable inode: ledger persistence atomically replaces `<id>.install.json`, so locking the ledger would not coordinate later opens. Coordination files contain no model bytes and are never replaced or unlinked by transfer completion/cancellation. They remain after cancellation; deleting them while another owner might exist could split coordination across different inodes. Unrelated transfer IDs remain independent.

The implementation uses Rust's standard File::try_lock, with contention reported as ResourceLimit and other failures propagated without an unlocked fallback. The [official Rust File documentation](https://doc.rust-lang.org/std/fs/struct.File.html#method.try_lock) records the API as stable since 1.89; the pinned 1.90 compiler/checks and a real host child-process test verify the implemented path. Locks coordinate cooperating application paths; they do not prevent raw filesystem modification by code that ignores the protocol, nor establish actual device/filesystem support. No new dependency or model-specific runtime is introduced.

Resume first checks current ledger identity/binding, then acquires ownership and rereads the bounded regular ledger before any part truncation. Foreign and unbound managed resumes still reject before creating coordination records. The reread prevents applying an old durable offset if a previous owner finished between the first observation and acquisition. Nonregular ledgers/parts, symlink ownership records and nonempty unknown ownership records are rejected without adopting or truncating them.

Finishing a managed transfer moves ownership into PreparedEngineImport. The guard survives both successful SQL staging and failed publication until that prepared owner actually retires; callers must release an old prepared capability before mutating resume. Read-only recovery does not acquire mutation ownership and can inspect recorded state while publication is still owned. Recorded completion remains distinct from current resource integrity.

The Host now keeps prepared imports in a private pinned cell with an ImportPublishing phase. The writer borrows prepared metadata while the phase retains ownership; idle cancellation cannot retire a publishing cell. Temporary writer references are released before restoring the phase and enabling off-writer retirement. Actual handle close precedes release of scope admission/library ownership. No filesystem open, hash, sync, unlock or provider cleanup is added to the writer. Idempotent metadata publication and a known committed success remain supported.

Native tests cover competing resume before tail truncation, exclusion after atomic ledger replacement, a separate process acquiring/rejecting ownership and releasing on process exit without Rust destructors, unknown/symlink coordination records, ownership through successful publication, and cancellation followed by actual retirement. Existing retry fixtures now release stale/cancelled prepared owners explicitly; Host fixtures observe retirement acknowledgement before resuming. This is groundwork for safe discard, not evidence that discard or installed SDK resource cleanup is already implemented.
