# ADR 039 — structured table-cell ink and recognition

Status: native Core/Host implementation; component/full validation recorded separately. Q071 row/column sizing/editing and broader backend acceptance remain open.

Q070 explicitly requires independent pen writing, recognition and correction in structured table cells. The existing table values alone did not satisfy that requirement. A table block now owns immutable observed strokes while each cell's stable ID identifies its logical ink region. Existing region snapshots and explicit proposal/correction/acceptance transport can therefore carry one cell's ordered digital ink without sending neighbouring cell strokes. Acceptance maps only Text/Numeric/Maths candidates into the associated typed cell value. Unsupported candidate kinds are refused; nothing silently repairs an expression or coerces code into a cell.

Capture is a separate revision-bound, idempotent authoring transaction. Its receipt binds exact target and stroke payload. Fresh content/exercise/block authority, visibility, stable identity and source order are checked before publication; failure rolls back both source rows and the receipt. Cell IDs already bound to another table's current or historical region, or colliding with known durable object identities, are refused. New capture retains previous editable text and original ink but marks the cell's new handwriting as awaiting review. All proposals remain block-revision fenced: edits to another cell conservatively require a new proposal rather than silently rebasing a stale one.

No new serialised block fields are needed, but table-region IDs gain a new meaning. Native subset v11 and SQLite/backup schema19 fence that meaning explicitly. Old tags reject current, historical and Undo-only bindings. Independent native copies remap cell IDs together with region/stroke IDs. Both encrypted backup formats preserve the source and target association. Derivative exports avoid duplicating accepted region text ahead of its table, and warn when unconverted cell handwriting is excluded.

Incremental capture exposed an existing Undo/Redo assumption: Undo correctly retained appended original observations, then Redo compared against a historical pre-capture source list and rejected it. Replay now requires that historical source IDs remain an exact prefix, compares presentation with that retained suffix accounted for, and still preserves actual raw source ownership. It does not ignore reordered or replaced observations. This applies to the shared block editing machinery and is covered by cell and existing authoring regressions. Accepting another region also preserves an existing block-level manual-correction marker, and saved cell cursors remap with independently copied cell IDs.

Coordinates remain observed table-source coordinates. Cell hit testing/physical sizing is a separate authoring/layout concern; this native contract does not infer or crop ink at a visual border, claim handwriting quality, introduce a raster pipeline or add production H.I. Source getters, scoped Host preparation and existing JNI region parameters remain the intended integration route; end-to-end platform acceptance must be established separately.
