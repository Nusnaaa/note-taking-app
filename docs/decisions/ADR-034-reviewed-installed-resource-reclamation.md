# ADR 034 — reviewed Removed-version resource reclamation

Status: Core/Store schema-18 implementation; Host lifecycle and JNI/Android adoption remain open. Full verification is recorded separately from component evidence. No production H.I. is introduced.

Only a current app-authorised, logically Removed version with a historical local resource locator can create a reclamation plan. Staged/Installed versions and an active SQL pointer refuse the flow. The target must be the version's exact UUID resource filename in the supplied private depot. A worker review exposes only descriptor/declared size, observed node kinds/sizes, consent provenance and required review choices. It retains a directory descriptor; Unix directory device/inode checks fence replacement after review. Other directory-identity platforms currently return Unsupported rather than silently omitting this check. Coordination is cooperative private-depot behavior, not protection against arbitrary privileged filesystem namespace replacement.

Review itself opens no model payload and creates no coordination file. Owner consent is separate: confirmation, unknown/legacy binding review, failed-retirement review and symlink review are explicit fields. No original import timestamp is invented for missing/invalid/unbound ledgers. A valid known foreign-library ledger always refuses deletion. Symlink review authorises unlinking only the known link name; targets are never followed or removed. Directories and other nonregular entries are retained for review; there is no recursive delete.

Preparation acquires both stable transfer ownership and an exclusive SDK-resource reservation. A live shared SDK/reader reservation blocks preparation even with every review flag true. A failed provider's deliberately retained process reservation also cannot be bypassed. After a previous process has ended, a persisted uncertain-retirement marker requires explicit review plus successful exclusivity; it is never silently reset. Facts must still equal the reviewed observations after ownership is acquired. Model hashes in descriptor metadata are not represented as freshly verified content hashes during deletion.

The metadata-only Store authorisation rechecks fresh app/library and exact Removed-version identity and commits Pending before issuing an opaque preparation-specific permit. Worker removal consumes that permit, checks deadline/control/directory identity and expected node facts, removes only resource/part/ledger names in that order and syncs the directory. Stable coordination files remain. Separate completion records Completed while the result still holds actual ownership guards. Errors after deletion do not imply physical or metadata rollback. The private historical locator remains on the Removed version for explicit uncertain-outcome recovery; it is not a readiness/presence guarantee and remains stripped from backups. Declared model size is retained as provenance, not a disk-space measurement.

Explicit Pending retry creates a fresh review and appends its consent/facts decision to the same action before further file work. Previously recorded import consent is labelled RecordedDecision only when every known payload/ledger name is already absent. Fresh observations may require additional consent; original request/provenance is not silently rewritten. Decisions and record/page sizes are bounded. Audit JSON contains no filesystem path, model bytes, directory descriptor or deletion capability. Core callers must supply current linked job authority; the future Host wrapper must retain its scope through actual off-writer guard retirement, including metadata publication barriers.

Schema 18 appends strict `engine_reclamations(id,version,payload)` with its version index. Payload validation binds SQL keys, known consent/review states and a matching Removed engine version without an active pointer. This table is separate from unpublished `engine_resource_actions`, whose prohibition on any published target remains intact. Whole-library JSON writes 18/reads known 9..18; streaming writes 18/reads 15..18 and appends index 32 after the schema-17 index 31. Older tags must omit the new table/stream segment; hidden extensions are rejected. Both formats preserve historical decisions without local paths or authority; restored libraries receive a new identity and missing local locators cannot grant reclamation. Notebook subset v10 is unchanged. Pending model-resource omissions remain visible.

This establishes deletion of known names at a reviewed location, not measured freed device blocks or global SDK shutdown. Remaining work includes Host/JNI/Android review/consent/lifecycle integration, real recogniser rights/quality, hard resource isolation/scheduling and the other backend acceptance gaps. Synthetic fixtures and local encrypted backup checks do not establish device/ART or proprietary SDK acceptance.
