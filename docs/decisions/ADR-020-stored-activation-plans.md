# ADR 020 — stored engine activation plans

Status: recorded backend decision; native Store and host preparation/publication implemented. JNI/provider and production controller adoption remain open.

Separate stored-engine activation into metadata capture, optional-worker preparation and durable publication. `Store::engine_activation_plan` captures the library identity, exact engine version, store generation and original access expiry without file I/O or a provider callback. The private plan prepares a recogniser or converter on an optional worker without borrowing the live Manager: load bounded local resource bytes, verify the recorded hash, probe a candidate with JobControl and extract the exact ready runtime. Resource buffers are zero-cleared.

`Store::commit_engine_activation` rechecks current app access, the original expiry/control, library/version identity and generation. A borrowed ReadyPublication guard preflights family compatibility and holds exclusive destination/candidate references across the callback-free SQLite transaction. Failed metadata/transaction checks leave the candidate holder and old live runtime intact. After the durable commit, publication is infallible under those exclusive borrows and returns the old DetachedRuntime for disposal after unlocking. Repeated consumed plans fail.

The transaction records the installed version and active pointer using existing tables; no new schema or inferred runtime readiness is introduced. Probe failure never replaces the old runtime. Another library or authored/configuration change invalidates the prepared generation. Separate later resource-file changes are not a new model-availability guarantee; current runtime lifetime and future reactivation still obey resource guards/verification.

This is a native Store API. Call preparation on an optional worker and dispose failed/old SDK holders after releasing locks. Existing synchronous activation APIs remain available under their prior caller-owned rules. Host execution/admission and durable publication are described below. Global scheduling/uninstall and hard allocation/worker isolation remain open. Installed metadata is still distinct from fresh runtime readiness, and adding these APIs installs no real model.

Host preparation adoption: `Host::engine_activation_plan` reserves only stored metadata on the writer. The resulting private host holder owns optional-work admission, descriptor bytes, original authority and library lifetime. Recogniser/converter objects enter only the caller's optional-worker preparation method. Preparation links cancellation to the scope and never borrows the live Manager. Capture, relock and close invalidate the holder; actual prepared SDK destruction uses the existing off-writer retirement lane, and library ownership remains held until it finishes. The private prepared holder deliberately exposes no raw runtime or Store capability. The prepared holder feeds the durable host publication operation below; JNI adoption remains open.

Host publication adoption: the optional controller calls `Host::commit_engine_activation` with a shared `Arc<Mutex<Manager>>` and a private prepared token. The synchronous caller retains strong leases through the reply; the mailbox carries weak references and no SDK callback payload. The writer tries the Manager lock once and returns ResourceLimit on contention, retaining the candidate. Authority and scope are rechecked before entering a private publishing phase. Scope/phase locks are released before the SQLite transaction; pen-priority signals can invalidate the linked control without waiting for database I/O. The private phase pins the SDK cell while the writer uses temporary references. The writer releases these references and the Manager before reopening retirement. Replaced runtimes remain in the cell for the existing off-writer retirement lane; close retains library ownership through actual destruction. Panic cleanup also queues the pinned cell.

Publication is admitted metadata work, with cancellation checks before and inside the transaction. A pen signal arriving after the final check may race the irreversible SQLite commit; a known successful commit remains successful, and the controller receives success. Cancellation does not roll back an already committed installation or acknowledge global runtime retirement. New optional inference remains subject to capture admission. No scope lock is held across fsync, probe or SDK destruction. Current app authentication changes are writer-ordered, and stale generation/version or foreign scope fails without installation. Durable host publication is now available in Rust; JNI/provider registration and production controller adoption remain open.

Verified SDK construction: `prepare_recogniser_with` / `prepare_converter_with` accept an optional-worker factory receiving only the typed Descriptor, temporary verified resource snapshot and linked JobControl. Typed family/input/privacy eligibility, current authority, byte bound and resource hash are checked before invoking it. Resource-backed metadata without a local resource is an integrity failure, and stored engine payload identity must match its SQL key. The factory cannot obtain a pathname, Store or live Manager from its arguments. It must load synchronously or retain its own protected copy; the core snapshot is zero-cleared after preparation. Existing preconstructed-adapter APIs delegate to the same path. Construction panic becomes WorkerFailed, and cancellation is checked again before probe/publication. A later change to the source file does not change the bytes handed to this factory; it still affects future reactivation, not an already loaded SDK. This does not audit SDK internals, grant model-use/publication rights or enable a model.
