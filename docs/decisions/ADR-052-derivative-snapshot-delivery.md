# ADR 052 — derivative snapshot, worker rendering and reviewed host/JNI release

Status: implemented; component verification recorded separately. Full scene/portability acceptance remains open.

Derivative export now captures a bounded authorized snapshot before rendering. The snapshot includes current visible blocks/layers, needed layouts, explicitly chosen visible ink and selected image bytes; rendering performs no live Store reads. Original samples remain unchanged. Converted-only capture does not read ink records. Current table ink/grid SVG uses the same placement logic with captured observations; original-coordinate SVG stays separate. Canvas-region selection still refuses partial blocks and original-ink output, and now explicitly refuses unsupported embed composition.

One host export slot is shared with native-copy export. Source capture checks current access/capture authority between operations. Caller-worker rendering, cropping, SVG/PDF generation and final verification carry linked cancellation, expiry and deadlines. Review exposes metadata/warnings rather than artifact bytes. A final explicit confirmation, fresh protected-scope verification and live-writer library/generation/access check precede output release. Cancellation remains checked through release. Worker close/reentry behavior follows the shared export lifecycle.

Snapshots and aggregate Markdown/assets are limited to 64 MiB; individual ink SVG assets remain limited to 8 MiB. Serialized block/source sizes are checked before materialization, and SVG point appends are incremental. PDF output is checked as chunks accumulate and after finalization. These are logical admission/artifact limits, not heap or timing SLOs. Cancellation is cooperative between operations; SQLite steps, image/font parsers and SVG-to-PDF conversion are not claimed interruptible mid-call. A shared image is captured once, its actual current/history reference scopes are freshly verified, and unrelated block bodies are not decoded. Empty exercise/region/app-locked selections retain their governing proof scopes.

The Store compatibility API uses the same capture/render implementation and still validates generation after rendering. Typeset PDF remains converted-only, requires an explicitly supplied local font and explicit page dimensions, and reports that saved canvas/view geometry and original ink are not rendered. Unsupported image/PDF/scene fidelity remains an error rather than hidden omission; complete scene/PDF-source packaging is unfinished.

The worker-only JNI transport has separate capture, render/review and confirmed finish phases with opaque host-bound non-reused handles. No registry lock spans work or a verifier callback. Close cancels or retires each phase; publication rechecks the live host to prevent orphaned jobs. Markdown is returned as UTF-8 bytes, assets as named binary arrays and PDF as binary bytes. The caller owns these deliberate outputs; closing the data wrapper clears those arrays, not caller-retained copies. No provider/filesystem publication, network access or automatic OS backup is introduced. Consumer rules already preserve the nested JNI constructors/callbacks. Fresh desktop JNI/R8 tests do not establish Android device acceptance.

No schema/native-document version change is needed. Reviewed provider publication, native-copy import delivery, full view/flow/physical rendering and full PDF/source interchange remain open.
