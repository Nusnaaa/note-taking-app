# ADR 037 — authorised Host content conversion

Status: native Host implementation; JNI/Android converter transport and complete backend acceptance remain open.

Content conversion consumes a move-only source created by the library writer from `Store::block` with current app/entity/block/exercise authority. An optional region must exist and have editable content. Only text, numeric, code and mathematical presentation content are admitted. Raw handwriting is not implicitly recognised or rasterised by this route. The capability retains block/region/revision identity; client JSON cannot substitute source content. Conversion returns a derivative and does not publish a recognition proposal or mutate a stored block. An output from an older revision remains explicitly labelled with that source revision.

Sources and prepared converter work occupy the same bounded processing scope as recognition and engine lifecycle operations. Existing count, aggregate source-byte and frame bounds apply. Capture priority, protection changes, relock, close and absolute access expiry invalidate the same authority. Dropped prepared work uses the existing retirement lane, so releasing an idle SDK reference does not run provider destruction on the library writer. Running callbacks execute on the caller's optional worker and retain their runtime until actual return. Native in-process callbacks remain cooperative; this does not claim hard isolation of uncooperative adapters.

Core `ConversionWork` now links scoped authority into the adapter's JobControl alongside caller cancellation, deadline and runtime validity. Both pre-call and post-call checks apply. The Host returns immutable output with engine descriptor, target format, source identity and unmodified fidelity/unsupported diagnostics after enforcing the output frame bound. Obtaining output checks the original authority and linked caller/runtime control again. Already copied output cannot be recalled; runtime retirement never edits an existing notebook.

Synthetic native integration tests cover literal code whitespace/numeric lexemes, runtime retirement after completion, capture/relock/close revocation, shared admission bounds, source protection and authoring during a blocked callback. Existing processing and recognition regressions run alongside them. These establish neither universal conversion fidelity nor real SDK licensing/quality, Android device performance, global process resource isolation or backend completion. The initial protection fixture's unauthenticated locking failure is retained separately from the corrected run.
