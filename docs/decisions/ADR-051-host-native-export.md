# ADR 051 — reviewed native-copy delivery through the host and JNI

Status: implemented; component verification recorded separately. Full portability acceptance remains open.

Native export now separates the immutable selected snapshot, caller-worker encoding/encryption and live-writer release. A host admits one opaque native-export snapshot at a time. Dropping a review or completed result releases admission; a stale held review must be explicitly closed/dropped, never silently evicted. No bytes are exposed by the review or completed-work types. Completed work retains its linked cancellation/deadline control through byte release. Release checks that control, originating host, access epoch/expiry, current app/scope authority, library identity and exact generation. Concurrent source changes refuse output rather than substituting newer content.

Platform verification, JSON artifact construction and encryption execute on the caller worker, with no host/registry mutex held across a callback. Existing JobControl cancellation/deadline is linked to the host access epoch and capture priority. Checks run at work boundaries, including after verification and encoding/encryption; cryptographic primitives are not claimed interruptible mid-call. External close cancels admission and waits for an active native-export worker. Reentrant close from its verifier refuses self-join and still cancels the work. Verifier panics are contained.

The native JSON format remains version 13. The existing 64 MiB decoder/encryption plaintext limit now also bounds counted snapshot JSON and retained JSON encoding, including the checked wrapper. Stored source/history bytes are counted before materialisation; entity/block selection is bounded by native subset limits. These are logical artifact/admission limits, not device heap or timing SLOs. Whole-library scale remains the streaming backup route. Current native-subset omissions and unsupported PDF packaging remain explicit and require the existing acknowledgment; no claim of complete v0.5.8 interchange is made.

The JNI review registry is host-bound, non-reusing and limited to 128 outstanding jobs, while the core admits one per host. Strict selection JSON cannot forge a review. Java close cancels a running job, and native close retires idle reviews. Registry publication checks the live host under the same lock ordering as close, preventing late orphan publication. Returned byte/recovery-key arrays are deliberately owned by the caller; closing the data wrapper clears those arrays, not caller-retained copies. Password snapshots and native secret decoding use zeroizing buffers. No file/provider writes, cloud backup or network activity are introduced.

This provides native-copy delivery only. Derivative host/JNI delivery, full PDF/source packaging, reviewed filesystem/provider publication and production Android integration remain unfinished. Desktop JNI/R8 tests are not device acceptance.
