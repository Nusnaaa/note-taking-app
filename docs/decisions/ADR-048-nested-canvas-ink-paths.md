# ADR 048 — nested canvas ink paths and transformed clip envelopes

Status: implementation/component verification in progress; complete view/flow/export/selection acceptance remains open.

A nested table page carries a root canvas entity/layer revision and an inner-to-outer sequence of embed ID/revision plus host entity/layer revisions. Every next embed must source the preceding host. Hosts must be canvases while traversal continues; a note may be the final host. Repeated surfaces, disconnected paths, stale revisions and inaccessible participants fail before delivery. All checks run again after source fragments are read. The algorithm is iterative and follows only the supplied path, not an inferred graph traversal.

Visibility follows the existing scene contract: the root table has its actual source layer, while nested embed objects belong to their host canvas's base layer. Each outer embed's explicit layer override controls its source canvas, including showing a base layer hidden in the default direct view. The outermost host's direct visibility still applies. This avoids both a blanket AND of all default visibility flags and a fallback that accidentally shows unresolved layers. Existing embed/content protection remains required for every participant.

Camera transforms compose from the table's source canvas through each embedding host. Each frame rectangle stays in its original host coordinates with a separate transform into the final surface. Consumers intersect these transformed rectangles; the backend does not replace a rotated rectangle with an axis-aligned bounding box or destructively clip observed samples. Transformed clip corners, matrices, points and continuity samples must remain finite.

The existing 8 MiB scene response budget includes the complete path/clip envelope. The source-fragment reader accepts an internal reduced byte budget. If the first contact fragment exceeds that space, its selected points shrink until a nonempty exact excerpt fits; cursors advance only by returned observations. A single observation plus metadata that cannot fit still fails explicitly. The public raw-source query retains its existing budget and API. Record-size/point validation and fresh access checks remain unchanged. These are response/resource bounds, not a process-memory or latency SLO.

`NestedCanvasTableInkScenePage` is available through the host query boundary. Direct and single-embed APIs remain supported. No persisted fields or model capability change, so native13/schema22 remain unchanged. Outer writing-view/screen transforms, text-flow layout, automatic follow-object references, complete SVG/PDF derivatives and pen/lasso workflows remain open. No production Android H.I., raster recognition or device-unit inference is introduced.
