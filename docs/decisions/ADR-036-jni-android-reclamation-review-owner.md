# ADR 036 — tracked JNI/Android reclamation review ownership

Status: boundary/controller implementation; component and full validators recorded separately. Broader backend acceptance remains open.

A trusted Java EngineReclamation owns one native scoped job across plan, filesystem review and explicit confirmation. Its stable action ID is allocated before review/file work. Review returns path-free facts while the actual Host review/directory descriptor remains in a native registry entry. A successful review restores that owned entry before returning metadata. Close/capture/relock/expiry/caller cancellation cannot revive it. Confirmation consumes the reviewed owner, prepares real exclusivity, records Pending, removes known names and records Completed. Known final SQL success is not discarded by a late cancellation check. Every error after confirmation may follow metadata/physical effects; history discovery and explicit retry remain required.

The Android bounded optional controller adds a tracked AutoCloseable ReclamationReview session, not just a completed asynchronous review result. Sessions stay in the controller's bounded ownership set across human confirmation. Controller close snapshots and closes every session as well as cancelling active/queued operations. Cancellation ownership remains attached through the operation-to-session handoff; operation completion releases its reference only after marking it finished. Session close revokes native work and removes the tracked session. Confirmation is single-use. The consumed review and its action identity attach to the operation before enqueueing, so cancellation of a queued confirmation retires it even when its action body never runs. Rejected submission also closes the consumed session. Existing native scope/retirement ownership keeps actual directory/resource disposal off the writer and retains library ownership until real retirement.

Typed immutable summary, file facts, consent choices and decision history contain no model path, bytes or live capability. Missing required review choices are rejected before consuming the session so the owner can correct their choices. Native preparation still rechecks observations and cannot bypass actual SDK/transfer guards even when every flag is true. Pending and Failure retain action identity; conservative metadata uncertainty never promises rollback or invents a durable Pending row when preparation failed. Java/native handles and review sessions themselves are not serializable.

The new nested JNI owner is excluded from Robolectric acquisition and included in class-loader identity regression checks. The aggregate JVM fixture includes two-stage/consent/replay/history, actual blocked SDK retirement exclusion, capture/close, explicit symlink-only removal and fresh app protection. R8 uses normal consumer rules and verifies fixture renaming. Android component cases exercise typed legacy consent/history, review ownership through controller/backend close and surviving handles, plus capture and uncertain identity retention. These are actual desktop JNI/API-35 simulation results with synthetic app-owned bytes/providers, not device/ART, real model quality/licensing or global resource-isolation acceptance. No production H.I. is introduced.
