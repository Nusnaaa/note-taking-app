# ADR 016 — owned engine activation probes

Status: recorded backend engineering decision; JNI/provider/device integration remains open.

The shared Manager already returns owned inference/conversion work. Local activation previously called adapter `probe` under a mutable Manager borrow. A provider transport using a manager lock must be able to release that lock before invoking provider code. Add `prepare_activation`, owned `ActivationWork::run`, and `complete_activation`.

Preparation requires explicit consent and verifies the declared local resource hash under existing rules. Denied consent preserves previous readiness. Reverification retires the old inference epoch immediately; failed integrity leaves the entry non-Ready. Successful preparation pins the exact adapter/descriptor and a distinct activation epoch without calling provider code. Pending, abandoned or cancelled activation stays Failed/non-Ready, matching the previous synchronous activation's fail-closed verification interval. No installed filename becomes readiness evidence.

Run the owned probe on an optional worker after releasing the manager lock. Check caller JobControl and the activation epoch before and after the callback; catch probe panics. Removal, replacement, new verification and Manager shutdown invalidate old activation epochs. A running callback retains its adapter/resources until it actually returns and its owned holders retire; cancellation is not forced termination.

Completion uses a private epoch-bound outcome and checks the current entry and JobControl again. Foreign, superseded, cancelled or replayed results cannot enable an engine or overwrite a newer entry. Successful completion enables the new runtime validity epoch; old inference work stays invalid. `complete_activation` borrows the completion mutably and consumes its outcome without dropping the adapter holder. Callers retain that holder until after releasing any manager lock, then retire it off writer. This prevents the completion method from invoking final provider/resource destruction while a manager lock is held.

The legacy synchronous `activate_local` remains a compatibility wrapper with its existing unbounded callback behaviour; it introduces no new arbitrary runtime deadline. New provider integration must use the owned path and an explicit caller job control. Durable installation, actual eligible stroke recognisers, model consent records, JNI provider registration, full resource/scheduling/retirement integration and hard worker isolation remain open. Synthetic probe tests are lifecycle evidence only; they do not establish model quality or licensing permission.

Provider error payloads can also own cleanup callbacks. The owned completion retains the original error until off-lock retirement and returns a content-free error classification instead. I/O kind is retained with a fresh standard error; provider storage/JSON payload errors become WorkerFailed. Cancellation does not drop a provider error payload under the manager borrow. The synchronous compatibility wrapper returns the original provider error as before. This distinction is covered by explicit destructor-lifetime and compatibility tests.
