# ADR 053 — prepared native imports and durable publication receipts

Status: implemented; verification is recorded separately. Backend acceptance remains open.

Native-copy import now separates caller-worker decoding, optional explicit credential decryption, format validation, independent identity remapping, hashing and fixed-row serialization from insert-only writer publication. The host reserves one transfer slot shared with native/derivative export. The prepared SQL values and input artifact each have a 64 MiB logical admission bound (the encrypted envelope allows its fixed overhead); these are not heap or timing guarantees. The existing interchange limits, including 100,000 blocks, remain unchanged. Original ink observations retain their values. Recovery titles gain a suffix only when it fits the existing title limit; otherwise the original title is retained and the review reports that count.

Publication requires explicit confirmation, acknowledgment of any source-declared omissions, fresh app proof when applicable, and a current library/generation/access stamp. Source omission strings are untrusted file metadata. Imported protection flags remain set, and import grants no scopes for newly assigned identities. Cooperative cancellation/authority checks cover worker phases and row insertion, including a check immediately before commit. SQLite primitives, cryptographic primitives and JSON parsing are not claimed interruptible mid-call. No callbacks run under the writer or bridge registry locks.

The host assigns an operation UUID before publication. Schema 23 adds `native_imports`, containing that UUID, the incoming artifact SHA-256, imported entity identities and completion time. Receipt and imported rows commit in the same transaction. A known commit returns its receipt without a later cancellation check. A lost transport response must be reconciled using the operation UUID; a missing receipt alone does not prove rollback while a worker is still pending. Retire pending work before deciding to start a new import. A replay of an already recorded operation with the same digest returns its original identities without another write; a different digest is rejected. The opaque host/JNI source and review lifecycle does not accept a caller-selected operation identity for publication.

Receipts are library-local operational metadata, included in both private backup encodings and validated during restore. Schema 22 and older archives cannot disguise nonempty receipt rows; genuine older libraries migrate with an empty receipt table. Native interchange remains version 13 and excludes these local receipts, as it already excludes other library-local operational journals. Receipts retain identities after trash/purge and are not a secure-erasure mechanism. The synchronous Store convenience import uses the same preparation/publication logic but does not claim transport reconciliation.

The JNI wrapper uses non-reusing host-bound handles, one-shot preparation/publication, bounded byte and UTF-16 copies with owned-copy erasure, cancellation on close, and a separate durable receipt query. A failure to allocate or deliver a Java response after commit leaves the receipt available. The Java wrapper does not replace a returned committed receipt with a concurrent-close error. Provider reads/writes, platform document publication, full portability/scene acceptance, real devices and the remaining backend gaps remain open.
