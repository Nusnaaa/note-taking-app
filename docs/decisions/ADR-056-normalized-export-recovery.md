# ADR 056 — normalized export attempts and paged recovery discovery

Status: implemented;45 focused and404 complete Android-module tests pass with lint/debug/release checks. Whole-backend acceptance remains open.

The device-private export catalogue moves from one JSON payload per publication (version1) to normalized version2 headers and file rows. Its purpose changes to `STEM-EXPORT-CATALOGUE-2`; notebook schema23 and native interchange13 are unchanged. No artifact body, credential or recovery key enters this catalogue.

Headers retain operation/library IDs, original sequence/time/format, selected tree/folder, file count, past outcome and sync acknowledgment. Parts retain ordered generated names, lengths, hashes and known document URIs. Initial intent creation is transactional. Folder and per-file URI acknowledgments now perform indexed incremental updates, with immutable plan fields, duplicate-binding refusal, monotonic completion and metadata-byte accounting. The provider worker updates its local part slots in place instead of copying/scanning the entire plan for every file. Completed outcomes are recorded only when every file URI is known. A compatibility full-record transition remains for failure reconciliation; it is no longer the successful per-file hot path.

The existing8MiB logical metadata admission bound is retained. Individual SQLite rows stay small; lookup iterates ordered file rows with cooperative cancellation and validates cached size/count against the reconstructed record. This removes the whole-payload CursorWindow problem without reducing accepted metadata to a smaller window-sized limit. It does not claim a hard heap, latency, cloud or device performance guarantee.

Known version1 catalogues are migrated atomically. Their original ordered records, IDs, library bindings, timestamps, tree/folder/file URIs, past states, sync facts and sequence gaps are preserved. Legacy JSON is read through bounded BLOB slices instead of a giant cursor value, with size/UTF-8/semantic validation and cancellation checks. The old table and purpose/version change only within the same transaction. Malformed input, an observed cancellation or an injected failure before commit rolls back the entire migration; unknown purposes, namespaces, future versions and symlink/foreign files are not silently repaired. New allocations continue after the largest preserved sequence.

`NotebookExports.history(before,limit)` returns immutable, library-scoped attempt headers using the validated `(library,sequence)` index and a descending keyset cursor. The caller can discover operation IDs after a restart, then reconcile a selected record. Paging does not contact providers, read all file lists or assert current availability. Entries describe past acknowledgments; relocking the app denies discovery through the existing native gate. Insertions after the first page do not shift older page boundaries. Limits are engineering admission bounds, not SLOs.

Focused tests cover genuine version1 schemas, preservation/rollback/malformed rejection, migration and cancellation beyond2MiB cursor size, normalized large lookup cancellation, near-budget incremental refusal, duplicate URI rollback, stable indexed cross-library paging and actual JNI/App-lock restart discovery. Existing publication/import/ownership checks are also run. The first migration fixtures used localization flags different from production and were rejected by strict namespace validation; they were corrected to the actual published `NO_LOCALIZED_COLLATORS` setup rather than weakening production validation. Exact attempts/results are retained separately.

This supersedes ADR055's current catalogue-normalization/discovery limitations. Real-provider/device tests, manual resolution of missing provider acknowledgments, complete scene/native PDF-source portability, broader resource acceptance and all other backend gaps remain separate. Production H.I. remains deferred.
