# ADR 046 — independent table copies and bounded vector scene pages

Status: implementation/component verification in progress. Complete scene/export/selection integration and backend acceptance remain open.

`CopyTable` copies the current visible table to an explicit entity, exercise or canvas-layer writing target. It preserves exact authored values/header structure, source-unit grid geometry, capture origins, block transform/display/correction state, explicit bounds/z and block lock. New block, local cell, global region and original-stroke IDs make the object independent. Original points, coordinate-space names, sensor/style/end provenance and capture sessions/sequences remain unchanged; hidden/retired observations remain retained. Source records are read and hash-checked one at a time. No inter-device coordinate conversion or automatic offset is inferred. Existing revision-bound placement commands can move the copy explicitly.

Insertion shares the existing writing-target contract, including exercise ordering and custom layers, inside one authoring transaction. Undo hides the new block and restores layer/bounds state; redo restores it. Exercise associations remain attached to hidden blocks under the existing separate membership-history design. Copies start fresh object history and do not duplicate capture receipts, external links, group membership, saved views or source Undo journals. Existing external references continue to identify the source. Source and target authority are checked again before publication.

A source block lock stays locked on the new object. Membership is attached during transaction-private construction before that final lock is persisted; the new ID is not granted to the caller's access capability. Failure rolls back construction. A fresh scope for the copied block is required for later reads of a locked copy.

`TableInkScenePage` supplies a block revision, source-index/point-offset cursor and explicit point budget (1–4096). Output is limited to the existing 8 MiB canvas-scene wire budget. Fragments identify the original contact, exact offset/count, source end/provenance/style and ordered observed points. A separate actual preceding point allows independent segment drawing without inserting duplicate samples into reconstructed sources. Fragments are rendering excerpts, not new captured strokes or raster recognition input. Cell reflow composes before the block transform; parent view/embed transforms remain caller/scene integration work.

Pages skip erased/hidden source records, refuse stale block revisions and invalid cursors, and recheck access before delivery. They read at most one original stroke record at a time, with the existing logical-backup 64 MiB cell bound checked before loading it. The original per-contact point validation still applies. This bounds response/record work; it does not claim an 8 MiB process-memory limit, hard latency or complete individual-record allocation isolation. A long valid contact is split into exact fragments rather than rejected merely because its whole response exceeds the page budget.

The older whole-scene query now reads records incrementally and returns either a complete result within the same wire budget or ResourceLimit. It never silently truncates. Larger callers use the paged query. No persisted fields change: native13/schema22 remain unchanged. Complete CanvasScene/nested-view integration, rendered derivative fidelity, pen/lasso selection and remaining resource/device/backend acceptance are still open. No production Android H.I. is introduced.
